# 鶴の花弁折りの途中変形を修正

対象は、公開ルートの9工程目で紙が裂けたように見える不具合と、反対側の11工程目。
鶴は18工程を維持する。折り目づけだけの往復は追加しない。

## 原因と変更

- 角の持ち上げと側面の折り込みを独立した軸回転で計算し、同じ紙の辺を別々の場所へ引いていた。
  `FoldOp.petal` では、側点を折り線の支点・持ち上げた角・隣の角からの距離で求める。
  前後の花弁折りとも、各三角面の辺長を保ったまま開いてつぶす。
- 隣接する紙面に不足していた折り線を加え、四つのページを対称に分割した。
  原紙の対角にある角2/6が羽、4/8が首・尾になる。
- 基本形の後半の袋で開く縁を3から1へ変更した。誤った縁を開くと、表裏と下の二つの束の配置が反転する。
  首の束は左、尾の束は右に収まり、色面が外側になる。
- 鶴の袋つぶしは180°で閉じる。176°のまま固定すると、次の花弁折りの支点が一直線にならず面が伸びる。
  他の基本形モデルは変更していない。
- 首・尾・頭の折り線は `foldFlap` で現在の紙面に切り込み、交点を前の工程でも素材の辺に追従させる。
  先端だけを横へ回す処理をやめ、実際の斜めの折り線で回す。首・尾は途中と終端を別工程にする。
- 厚みゼロの面が重なってちらつくため、鶴だけ `renderLayerSeparation` を有効にした。
  `renderFaceOffsets` が平らになる直前の配置から表示の層順を作り、裏返すときは束をそのまま反転する。
  面法線方向の微小な表示オフセットをWebGL・SVG・裏面率の監査で共有し、物理頂点や折り線は変更しない。
  これは紙厚の厳密解や衝突判定ではない。
- 既定の視点を上側へ移し、完成時に羽が首と頭を隠さないようにした。

## 検証

- 回帰テスト113件成功。既存の33作品の工程分割、コップの共有辺、JSON往復を含む。
- 鶴の全18工程を0.025刻みで調べ、面内の全頂点間距離と三角形面積の誤差は1e-8未満。
  原紙の全領域を保ち、内部の辺は必ず二面に共有され、内部切断はない。
- 花弁折りの境目を前後に動かしても連続し、片方を持ち上げる間は他の角が動かない。
- 基本形・花弁折りの完了時と完成時を正面から走査して、外側が色面であることを確認。
  表示オフセットは0.001未満で、物理座標に影響しない。JSON復元でも同じ表示になる。
- ローカル実画面で9/11工程目の途中停止と回転、完成形を確認。
- `npm run build` 成功。`npm run lint` は既存警告6件、エラーなし。
  `npm run audit:models` / `npm run audit:references` 完了。

## 残る範囲

首・尾をさらに細くする折りと、層の間へ差し込む厳密な中割り折りの動きは簡略化している。
その案内を日英で残した。面の伸びや切断がないことと、実物の全層の動きが一致することは別であり、
後者を保証したものではない。他作品の既知の曲面・複雑な折りの近似も今回の修正対象外。
