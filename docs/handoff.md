## 2. 次にやること(優先度順)

### A. ひよこ・ねこの「辺が伸び縮みする」工程を直す

2026-08-14 に導入した**辺の長さの点検**(`CLAUDE.md`「辺の長さで『取り残された頂点』を
自動検出」)で、静止状態なのに辺の長さが変わる作品が2つ残っている。

- **ひよこ(chick)**: ❶の縦折り(t=1)で辺 1-7 が 1.667 → 0.335。原因は
  体の面 `[7,6,13,14,1]` と `[7,10,11,12,1]` が**折り線 x=0 で分割されていない**こと。
  折り目をつける工程で紙がねじれて見える。直し方は、
  x=0 と辺 13-14 / 11-12 の交点((0,±0.823)付近)に頂点を足して4面を8面に割り、
  中心の頂点3も体の面に入れる。**面を割ると層順が変わるので、直したあとに
  「裏面が見えている割合」と完成形の縦横比を測り直すこと。**
- **ねこ(cat)**: t=2 で辺 19-20 が 0.43 → 0.09。19/20 は「てっぺんフラップの
  付け根の複製頂点」なので、z 補正の副作用の可能性が高い。まず見た目を確認してから。
- **鶴**は中割り折りの工程で必ず出るが、これはエンジンの reverse 折りが
  1頂点だけ回す仕様によるもの。**直さない。**

## 4. 作業のやり方(最低限)

```bash
npx tsc -b && npm run dev            # 型 → 起動
node tools/zu-measure.mjs fetch <名> # 折り図の取得(画像名は zu.html から)
```

- 画面の検証は `window.__origami.setT(t)` / `getPositions()` / `getModel()`。
  **「角が○○に来る」という見本の目印は必ず数値で確認する。**
- 新しい作品/折りを足したら、**辺の長さの点検**(§2A)を必ず1回通す。
  折り線の向こう側の頂点を `moving` に入れ忘れる事故がこれで消える。
- 完成形の縦横比を折り図の完成図(`zu-measure.mjs bbox`)と比べる。
- 新しい作品を足したら `src/App.tsx` の MODELS と `src/catalog.ts` の CATEGORY_OF、
  `CLAUDE.md` の作品項目、`docs/verify-models.md` の表を更新する。
- 1作品 = 1コミット。何が見本と違ったか/どう直したかを書く。
