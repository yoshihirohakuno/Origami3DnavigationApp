# 作品追加のループ(実装役 ↔ レビュー役)

新しい作品を1つ足すたびに、**実装役(メインのセッション)** と **レビュー役(別エージェント)** が
1往復する。人(ユーザー)は「呼ぶ基準」に当たったときだけ呼ぶ。

    候補を選ぶ → 折り図を実測 → 実装 → 自己検証 → レビュー役に出す
      → 指摘を直す → 再レビュー(指摘があった場合) → コミット&プッシュ → 次の作品へ

レビュー役の手順書は `docs/review-model.md`。エージェントの定義は
`~/.claude/agents/origami-zu-reviewer.md`(中身は薄く、この repo の手順書を読ませている)。

## 1周のやること(実装役)

1. **候補を選ぶ**
   - おりがみくらぶに折り図がある作品だけ(原典のない独自設計は禁止。過去3回とも差し替えになった)
   - `docs/handoff.md` の「次にやること」に読みかけの候補があればそれを優先する
   - 折り図を `node tools/zu-measure.mjs fetch <名>` で取得(`tools/.zu/` は gitignore)
   - **パネル数が10を超える / 立体的にふくらませる工程がある**ものは、その旨をメモに書いて後回し
2. **折り図を読む**。全パネルを画像で見て、工程・折り線・色の出方を書き出す
   - 目印(1/2・1/3・角の二等分線・辺に重なる)があるなら**厳密値**を採る。実測はその裏づけ
   - 目印がないときだけ実測値。**複数のパネルで測って平均**を採り、値の出どころをコメントに残す
   - 読めない工程は**推測で作らない**(→ 呼ぶ基準4)
3. **実装**。`src/models/<id>.ts` を書き、`App.tsx` / `catalog.ts` / `tools/audit-cover.mjs` に登録
4. **自己検証**(下の「合格の条件」を全部通す)
5. **レビュー役に出す**(Agent tool、`subagent_type: origami-zu-reviewer`)
   - 渡すもの: 作品 id、原典の URL、モデルのファイルパス、自分が採った折り線とその根拠
   - **自分の測定値は「検算してほしい数字」として渡す**。信用させない
6. **指摘を直す**。直したら数値を取り直し、直った/直せない理由を1行で書く
7. **コミット&プッシュ**(1作品=1コミット。何が原典と違ったか・どう直したかを書く)
8. `CLAUDE.md` に作品の項、`docs/handoff.md` に作品数と次の候補を更新

## 合格の条件(これを全部満たすまで次へ行かない)

| 見るもの | 基準 | 出し方 |
|---|---|---|
| 色の出方 | **裏面% が折り図の全パネルと一致** | `auditModel` を工程ごとに |
| 等長性 | 静止状態(整数 t)で **0.05 未満** | 展開図の辺長と各 t の辺長を比較 |
| 完成形の形 | 折り図の完成図との**縦横比が ±5%** | 完成形の bbox |
| 折り線 | 目印のあるものは**厳密値**(近似で書かない) | コードのコメントに根拠 |
| 型・lint | `npx tsc -b` が通る。oxlint の警告は既存の4件のみ | |
| 記録 | CLAUDE.md / handoff.md を更新 | |

## 人(ユーザー)を呼ぶ基準

**呼ぶ**(AskUserQuestion で、選択肢と推奨を出して1回で聞く):

1. **原典がない、または折り図が読めない** — どの層を折るのか確定できない工程がある
   (例: えんばん❹、さかな❺)。推測で作るか、後回しにするかはユーザーの判断
2. **既存作品の見た目が変わる** — 完成形の色が変わる、ライブラリのカードの絵が変わる
   (例: 正方基本形を白面スタートにした件)
3. **原典と工程が構造的に違う既存作品を作り直すか** — 鶴・箱の前例。作り直しは大工事になる
4. **作品の差し替え・削除**(ことり→ひよこ、ふうとう→てがみ、さいふ→ぴあの の前例)
5. **レビューで指摘された点を2周直しても数値が折り図と合わない** — 設計の判断が要る
6. **エンジン(`src/engine/*`)の仕様を変える必要が出た** — 全作品に影響する

**呼ばない**(実装役が決める):

- 目印のない折り線の実測値、面の事前分割、複製頂点と z 補正の入れ方
- 層順の直し方(残差角の階段・direction の明示・軸に浮いた頂点を使わない)
- 難易度・分類・説明文・注意書き・コミット文言
- 新しい分類の新設(足したら報告する。例: たべもの)
- レビューの指摘のうち、数値で白黒がつくもの

呼ぶときは**手を止めない**: 判断待ちの作品は保留にして、依存しない作業(記録の更新、
次の候補の折り図読み)を先に進めておく。

## ループの回し方

    /loop 新しい作品を1つ追加して、origami-zu-reviewer にレビューさせ、指摘を直してからコミット・プッシュして

間隔を書かない `/loop` は自分でペースを決める(1周が終わったら次を始める)。
止めるときは `/loop` を止める操作か、「ループを止めて」と言えばよい。
