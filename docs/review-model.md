# 作品のレビュー手順(レビュー役のエージェント向け)

このアプリの作品データ(`src/models/*.ts`)を、**原典の折り図から独立に検算**する。

**大原則: 実装役が出した数値を出発点にしない。** 折り図を自分で測り、自分の値と
コードの値を突き合わせる。一致したときだけ「合っている」と言える。
実装役の測定値は「検算してほしい主張」であって、根拠ではない。

## 手順

### 0. 前提をそろえる

    cd ~/Origami3DnavigationApp
    node tools/zu-measure.mjs fetch <名>     # 折り図がまだ無ければ(tools/.zu/ に入る)

折り図の画像は `tools/.zu/<名>.png` を Read で**目で見る**(パネルの構成・矢印の向き・
色の出方は画像を見ないと分からない)。細部は `sips` で切り出して拡大する。
ピクセル実測は `tools/zu-measure.mjs`(map/bbox/runs/outline/probe)か、
`readBmp`/`isBlank`/`isColor` を import した使い捨てスクリプト。

**注意**:
- GIF の透明画素は alpha=0 で RGB=0。「透明 or 白 = 地」で判定する(黒と間違えない)
- **パネルごとに縮尺が1割ずれる**。1枚のパネルの数値を信じず、別のパネルと突き合わせる
- 灰色・白黒の作品は `isColor`(有彩色)が効かない。輪郭と明度で判定する
- 折り図は手描き。目印(1/2・1/3・二等分線・辺に重なる)に一致するなら**厳密値が正**で、
  実測はその裏づけ。実測と厳密値が 0.02 ずれていても、目印があるなら厳密値を採る

### 1. 工程が原典と同じか

パネルの数・順番・「どの層を折るか」がコードの `steps` と対応しているか。
見た目が似ていても、**工程の順番や折る層が違えば「一致」ではない**
(`docs/verify-models.md` の基準)。違うなら、どのパネルとどの工程が食い違うかを書く。

### 2. 折り線を検算する

各工程について、**自分で測った折り線**とコードの値を比べる。

- 目印があるのに近似値が書かれていたら指摘(例: `0.414` ではなく `√2-1`)
- 目印がないものは、自分の実測値と**0.03 以上**ずれていたら指摘。
  そのとき「どのパネルのどの線を測ったか」を必ず添える
- 「角が○○に来る」という主張は、その着地点を自分で測って確かめる

### 3. 色の出方を工程ごとに突き合わせる

    // ブラウザで
    const { auditModel } = await import('/tools/audit-cover.mjs');
    const m = (await import('/src/models/<id>.ts')).<id>Model;
    await auditModel(m);   // t=0..完成 の「裏面(白)が見えている割合%」

t=0 が 0 なら色面スタート、100 なら白面スタート。**折り図❶と一致するか**。
以降の各値が、対応するパネルの色の出方と合うか(一面が色なら 0 に近い、
白い部分が半分なら 50 前後)。合わなければ層順の疑い。

**表だけでなく裏側も見る**(最前面ではなく最背面の面の向きで同じ計算をする)。
表だけ直っていて裏が白い、という直し方があり得る。

### 4. 幾何を検算する

- **等長性**: 展開図の辺長と各 t の辺長を比べ、静止状態(整数 t)で 0.05 以上のずれが
  あれば「`moving` に入れ忘れた頂点」か「折り線をまたいだまま分割されていない面」。
  どの辺・どの工程かを書く
- **完成形の縦横比**を折り図の完成図のピクセル実測と比べる(±5%)
- 面が**その作品で使う折り線すべて**で事前分割されているか(折って戻すだけの線も含む)

### 5. コードを読んで探す(既知の落とし穴)

- **軸に、前の工程で z 方向に浮いた頂点を使っていないか**(軸が傾いてフラップが
  奥へ回る。ぺんぎん❺❻・ぴあの❺・水風船基本形❺の再発源)
- **うらがえしの直後の折り**で、自動符号のまま(束が -z 側に移るので `direction` が要る)
- **「折って開く」工程の戻しの符号**: 直前の valley の自動符号が -1 なら戻しは +1。
  戻した直後に全頂点の z が 0 に戻るか
- 多層のフラップで**残差角の階段**が工程ごとに入れ替わっているか
- 複製頂点の**座標コピーミス**・**頂点順序(法線)の左右非対称**
- `sheetColors` は front=紙の色面 / back=白い裏面。白面スタートは `backSideUp` で表す
  (front/back の反転で表現していたら指摘)
- `App.tsx` / `src/catalog.ts` / `tools/audit-cover.mjs` への登録漏れ

### 6. 仕上げの確認

    npx tsc -b            # 通ること
    npx oxlint src        # 警告は既存の4件(CreasePattern×3, i18n×1)だけか

`CLAUDE.md` に作品の項があるか、`docs/handoff.md` の作品数が更新されているか。

## 返し方

**指摘は「数値の根拠つき」で、重い順に並べる。** 各項目に:

- どこ(ファイル:行 / 工程番号 / パネル番号)
- 何が食い違うか(**自分の測定値 vs コードの値**)
- どう直すか(分かるなら)

最後に一行で判定を書く: **合格** / **要修正(N件)** / **判断が要る(理由)**。

「判断が要る」は、`docs/model-loop.md` の「人を呼ぶ基準」に当たるとき
(折り図が読めない、既存作品の見た目が変わる、原典と構造が違う 等)。
そのときは**自分で決めずに、選択肢と推奨を書いて返す**。

指摘が無いなら無いと言う。**粗探しのために弱い指摘を並べない**
(このループは「弱い指摘を潰す作業」で止まるのが一番の失敗)。
