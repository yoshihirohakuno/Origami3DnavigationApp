## 確認した資料

[Origami-Fun のバラの折り図](https://www.origami-fun.com/origami-rose.html) をPDFで確認した。図はねじり、花の立体化、底、花びらの丸みを区別している。折り図の画像とPDFはローカルのGit対象外フォルダーだけに置き、リポジトリへ転載していない。この花全体の材料の対応はまだ未確定。

通常の中央四角ねじりでは、周囲の面を単純な独立回転で畳むと閉じた紙のループを満たせない。[Hull と Urbanski の研究](https://arxiv.org/html/1809.04899) は中央の対角線を追加した連動経路を示している。今回の試作は case 1 / curve A の角度関係を使う。

制御角を `theta` とすると、対応する角度は `phi=2 atan((sqrt(2)-1) tan(theta/2))`。中央の追加折りは、今回の固定面と軸の向きでは `zeta=-2 atan((sqrt(2)-2) tan(theta/2))`。

論文の符号をそのまま逆向きの固定面へ当てはめる候補は、外側の長方形に最大約0.5の寸法誤差が出たため採用しない。正しい軸向きと角度を使う候補では誤差は約4.4e-16。

## 実装

- `src/experiments/roseTwistStudy.ts`: 16頂点・10面の連続した正方形一枚。中央の二つの三角形、四つの周囲の四角形、四つの外側の長方形を、解析的な角度で連動させる。
- 四角形の元の四隅は、実際の長方形の二辺が直角になる閉鎖条件から求める。目標の頂点位置への補間や、紙のスケール変更ではない。
- 0から4は中央を曲げながらのねじり、4から6は周囲の折りを閉じたまま中央を開く。二つの連動動作を六つの停止位置に分ける。後半は折り目を付けて戻す準備工程ではなく、本体を平らなねじり形へ整える動作。
- `FoldStudyPreview.tsx`: 既存の開発用試作画面を共通化。既定では従来の `computeFoldState` を使う。バラだけが専用の `stateAt` を渡す。
- `BeetleStudyPreview` は同じ初期モデル、題名、操作を保持する。公開UIと折りエンジンは変更しない。
- `/tools/rose-study.html` は開発時だけ起動する。本番ビルドのJS/CSSは前回と同じ出力ハッシュ。

`OrigamiModel.steps` の回転配列は空で、姿勢はアダプターが計算する。これを通常の公開折りデータとして誤登録しない。将来の花びらの細分割、面の追従、後続操作への接続は別途必要。

## 検査

新規7テストが成功。

- 原紙面積4、統一した面の向き、内側の自由な境界がないこと、全体が一つの材料の隣接グラフになること。
- 中央の半対角線長 .1/.25/.4 の三条件で、1/256工程間隔・各1537姿勢の全パネルの点間距離を検査。許容誤差1e-9。固定する中央三角形も動かない。
- 四つの外側の長方形で、二辺の直角と四隅の閉鎖条件を769姿勢で確認。
- 三条件・各769姿勢で横断交差を検査し、検出なし。有限サンプルであり、全連続時間や実物での折り方の証明ではない。
- 六つの停止位置の前後、ねじりから中央を開く切り替えで不連続がない。終端は平らな四角形で、元の四隅は半幅.75の四角の角に到達する。
- 解析姿勢と矢印、最後のガイド非表示、入力範囲、未完成表示と公開除外を確認。

ブラウザーでは2→3.00と4→5.00の単独再生停止、6.00のねじり終端を確認した。姿勢アダプターによる途中の立体形を表示できている。ただし6.00の平らな重なりには、深度バッファ競合の縞が出ている。層の順を一括で決めて紙を離す方法では修正せず、未解決の描画課題として記録する。

全463テスト成功。最終版の新規7テストも単独で再実行して成功。`npm run build` 成功、`npm run lint` は既存6警告のみ。本番ビルドの500KB超の警告は既存のもの。

共通化したカブトムシ画面でも、従来の題名・144工程・111→112.00の単独停止を確認した。バラの途中姿勢の画像は `tools/.zu/rose-twist-study-2026-10-07.png` に保存（Git対象外）。
