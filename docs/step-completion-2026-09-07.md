# 工程番号と完了時の形をそろえる

鶴の4工程目で下の先端が重ならず止まる、という報告への修正。

原因は、工程一覧の4を選ぶと `t=3`、つまり「3を終えた、4を折る前の姿勢」へ移動していたこと。
画面の番号と説明は4なのに、袋をつぶす動きはまだ再生されていなかった。
幾何計算では `t=4` まで進むと下の先端6/8が一致し、反対側も `t=7` で先端2/8が一致する。
今回は既存の折り形状を変更せず、ナビゲーションの選択・停止・番号の対応を修正した。

- 一覧から工程を選ぶと、その工程の開始姿勢から完了姿勢まで、一工程だけ再生する。
- 完了後も、その工程の番号・説明・選択表示を保つ。「次へ」で次の一工程を実行する。
- 「折る前」「折りの途中」「この工程は完了」を日英で表示する。
- 完了時に次の工程の矢印を出さず、紙の形を確認できるようにする。
- PCとスマホの一覧画像を各工程の完了形に統一。完了済みの現在工程も選択色を保つ。

`computeFoldState` の整数位置で次の操作を予告する仕様は、エディタやモデル計算のために維持する。
ナビだけ `computeNavigationState` を使用する。座標は同じで、整数位置の工程番号・進行度・ガイドを
完了した工程へ合わせる。描画用の層間隔も同じになることを確認した。
`buildStepDiagrams(model, 44, 'after')` がナビ用。既存の `before` 表示も利用できる。

検証: 回帰テスト116件成功。鶴4/7の先端一致、全33作品の完了番号・座標・層間隔、
袋つぶしと花弁折りの完了サムネイルを追加検証した。ビルド成功、lintは既存警告6件のみ。
実画面でも4の選択から完了、次へで5、反対側の7、戻る操作を確認した。

鶴18工程・全33作品の工程数と折り目づけ往復の省略は変更していない。
首・尾の細幅化と中割り折りの簡略化など、既知の形状の制約は引き続き残る。
